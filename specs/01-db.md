# Base de datos

## Estado

Aceptada

## Objetivo

Crear los scripts necesarios para todo el proyecto.

Se deben crear los archivos .sql de acuerdo al nombre en la implementación.

## Implementación

### 01-init.sql

Se crea la base de datos `rutina` si no existe.

Se crea un role si no existe con el nombre `rutina_usr`, tendrá habilitado el login y utilizará una contraseña definida durante el proceso de instalación/despliegue. La contraseña no deberá almacenarse en el repositorio.

La contraseña se modificará manualmente al instalar en producción para evitar fallas de seguridad.

La contraseña por defecto en el archivo sql será un string vacío.

Se conecta a la base de datos `rutina`.

Se habilita la extensión pgcrypto en la base de datos rutina si no existe.

### 02-tablas.sql

#### usuario
Contiene la información de los usuarios autenticados.
Los campos con el tipo de dato a integrar son:

* id - uuid - llave primaria - autogenerado
* correo - text
* nombres - text
* apellidos - text
* pass - text
* activo - boolean - true por defecto
* creacion - timestamptz - now() por defecto
* modificacion - timestamptz - puede ser null

#### refresh_token
Contiene los tokens de sesión de  usuarios.
Los campos con el tipo de dato a integrar son:

* id - uuid, autogenerado - llave primaria
* usuario_id - uuid - llave foranea hacia usuario.id
* hash - text
* creacion - timestamptz - now() por defecto
* vencimiento - timestamptz

#### tarea
Contiene la información de las tareas.
Los campos con el tipo de dato a integrar son:

* enum `tipo_tarea` con los valores `unica`, `recurrente` y `flexible`.
* id - uuid - autogenerado - llave primaria
* usuario_id - uuid - llave foranea hacia usuario.id
* nombre - text
* descripcion - text
* tipo - tipo_tarea
* hora_inicio - time - puede ser null
* hora_fin - time - puede ser null
* fecha_inicio - date
* fecha_fin - date - puede ser null
* recurrencia - text
* activo - boolean - true por defecto
* creacion - timestamptz - now() por defecto
* modificacion - timestamptz - puede ser null

#### ocurrencia
Contiene una instancia de una tarea.
Los campos con el tipo de dato a integrar son:

* enum `estado_ocurrencia` con los valores `completada`, `cancelada`, `pospuesta`
* id - uuid - autogenerado - llave primaria
* tarea_id - uuid - llave foranea hacia tarea.id
* estado - estado_ocurrencia
* fecha_ejecucion - date
* creacion - timestamptz - now() por defecto
* modificacion - timestamptz - puede ser null

#### nota_ocurrencia
Contiene notas adicionales de la ocurrencia.
Los campos con el tipo de dato a integrar son:

* id - uuid - autogenerado - llave primaria
* ocurrencia_id - uuid - llave foranea hacia ocurrencia.id
* nota - text
* activo - boolean - true por defecto
* creacion - timestamptz - now() por defecto
* modificacion - timestamptz - puede ser null

#### lista_ocurrencia
Contiene un listado de sub-tareas de la ocurrencia.
Los campos con el tipo de dato a integrar son:

* id - uuid - autogenerado - llave primaria
* ocurrencia_id - uuid - llave foranea hacia ocurrencia.id
* nombre - text
* completada - boolean - false por defecto
* activo - boolean - true por defecto
* creacion - timestamptz - now() por defecto
* modificacion - timestamptz - puede ser null

### 03-funciones.sql

Nota: Adicionar security definer solo si está explicitamente definido.

#### uid
* Función helper para RLS que permite obtener la identidad del usuario autenticado.
* Debe ser SECURITY DEFINER.
* Obtiene el identificador desde el parámetro de contexto `app.usuario_id`.
* Si el parámetro no existe, retorna null.
* Si existe pero no contiene un UUID válido, retorna null.
* Consulta a la tabla usuario que el usuario con el id exista y esté activo.
* Si el usuario no existe o no está activo, retorna null.
* Si todo es válido, retorna el usuario_id como uuid.

### 04-roles.sql

* Se revocan todos los permisos del rol public en el schema public
* Se autoriza al role rutina_usr usar el schema public
* Se autoriza al role rutina_usr a realizar select, insert, update y delete en todas las tablas del schema public.
* Se autoriza al role rutina_usr a ejecutar todas las funciones en el schema public.

### 05-rls.sql

Todas las reglas de seguridad serán para el usuario rutina_usr.
Se debe habilitar rls en todas las tablas.
Para las reglas que necesiten saber si el usuario está autenticado se utiliza la función uid()
Cuando se refiera a 'Todos los usuarios' sin especificar si están autenticados o no, se incluye usuarios autenticados y no autenticados.

#### usuario
* Todos los usuarios pueden consultar y crear registros.
* Los usuarios autenticados pueden modificar su propio registro
* Ningún usuario puede eliminar registros.

#### refresh_token
* Todos los usuarios pueden consultar registros.
* Los usuarios autenticados pueden crear y eliminar registros si el registro les pertenece.
* Ningún usuario puede modificar registros.

#### tarea
* Los usuarios autenticados pueden consultar, crear y modificar registros si el registro les pertenece.
* Ningún usuario puede eliminar registros.

#### ocurrencia
* Los usuarios autenticados pueden consultar, crear y modificar registros si la tarea padre les pertenece.
* Ningún usuario puede eliminar registros.

#### nota_ocurrencia
* Los usuarios autenticados pueden consultar, crear y modificar registros si la ocurrencia padre pertenece a una tarea padre que les pertenece.
* Ningún usuario puede eliminar registros.

#### lista_ocurrencia
* Los usuarios autenticados pueden consultar, crear y modificar registros si la ocurrencia padre pertenece a una tarea padre que les pertenece.
* Ningún usuario puede eliminar registros.

### script.sh

Todos los scripts de la carpeta /db se ejecutan hacia el contenedor de docker de postgreSQL.
Los scripts sql se ejecutan en el orden de su numeración, desde 01-init.sql hasta 05-rls.sql.
El contenedor tiene el nombre de saas-postgres.

El arhcivo 01-init.sql es el único en ejecutarse con la base de datos de `postgres`
El resto de archivos se ejecutan con la base de datos `rutina`.
Se deben adicionar textos que se muestren en la consola mientras se ejecutan los scripts.
Si un script falla, se finaliza la ejecución.
